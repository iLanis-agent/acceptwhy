How the spec reads this

RFC 9110 section 12.4.2: the q for a representation comes from the most specific media range that matches it - an exact type/subtype with parameters outranks an exact type/subtype, which outranks type/*, which outranks */*. The header's order does not matter; specificity and q do. q=0 means "not acceptable". If nothing survives, the correct response is 406 Not Acceptable. Ties in q are the server's free choice - here, first listed wins.
